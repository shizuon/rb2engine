新增可选的 **「尝试修复 Grid 偏移（实验性）」** 开关，默认关闭。
开启后可选择 **「严格」** 或 **「宽松」**，默认严格。

## 使用方式

1. 选择 U 盘并读取曲库。
2. 勾选「尝试修复 Grid 偏移（实验性）」，选择严格或宽松。
3. 转换完成后查看报告，确认哪些曲目进行了调整、哪些保留了原网格。

保持原 BPM、拍间距、Cue、Loop 和音频。只对判断一致的曲目调整拍点的
整体时间偏移或小节第一拍位置。原始网格保留在数据库中，关闭开关后
重新转换可恢复；桌面端重建现有数据库时会先备份。

模型已随 Windows 和 macOS 安装包提供，可离线运行，无需另装 PyTorch。
本版没有加入变速分析，也不从零重建缺失的网格。

## 下载

- **Windows x64**：解压 `rb2engine-0.8.0-windows-x64.zip`，运行 `rb2engine.exe`。
- **macOS Apple Silicon**：解压 `rb2engine-0.8.0-macos-arm64.zip`，打开应用。
- **Python CLI**：`rb2engine-0.8.0-py3-none-any.whl`；此功能需安装 `grid-repair`
  可选依赖和音频解码工具。
- 下载后可用 `SHA256SUMS` 核对文件。

## 验证与范围

节奏不明确、偏移过大或检测结果冲突时保留原网格。详细报告记录所用
档位和检测依据，便于回看具体调整。

本地回归通过 1,068 项测试及 19 项子测试，覆盖率 86.18%。
新增测试覆盖两档差异、固定 BPM、原网格恢复、Cue/音频保留、记录篡改和
仅修改 adjusted grid 的校验失败。Windows/macOS 打包流程还通过实际
应用界面运行内置模型，修正自制音频中刻意加入的时间和小节错位。

这仍是实验性修复。模型一致不等于音乐上的判断一定正确；物理 DJ 播放器
上的显示和播放未由这些测试验证，演出前仍需试听检查。

包含此前的首拍编号、可选 ANLZ/封面回退和 macOS 版本显示修复。
完整算法、离线模型来源和验证边界见
[Grid alignment](https://github.com/shizuon/rb2engine/blob/main/docs/grid-alignment.md)。

CLI: `rb2engine convert /path/to/USB --repair-grid --grid-mode strict`，宽松档使用
`--grid-mode majority`。默认转换及 `--dry-run` 不加载模型。
